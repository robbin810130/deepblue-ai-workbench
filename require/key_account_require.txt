# 大客户档案模块需求文档 (key_account_require.txt)

## 1. 功能描述
大客户档案模块用于集中管理公司大客户的详细档案信息，包括客户基本情况、组织架构、业务需求、技术对接、售前痛点及解决方案等维度。支持档案的新增、编辑、分页查询、客户名称过滤，以及每次修改前的快照记录与历史追溯。编辑界面采用左右分栏布局，右侧可通过输入框和文件上传调用 Dify 工作流，自动生成左侧字段内容。

## 2. 核心流程

### 2.1 列表查看
1. 进入大客户档案模块，分页展示所有大客户档案数据。
2. 支持通过客户名称关键词过滤搜索结果。
3. 列表展示字段：客户名称、创建时间、最后修改时间。
4. 列表支持分页，每页默认 20 条，可切换每页条数。

### 2.2 新增大客户档案
1. 点击「新增」按钮，打开新增页面（左右分栏布局）。
2. 左侧为表单字段区域，包含以下字段（均为多行文本输入，支持换行保存）：
   - 客户名称（单行输入）
   - 售前
   - 基本情况
   - 组织架构
   - 需求业务
   - 技术对接
   - 售前痛点
   - 优识介入
   - 解决方案
3. 右侧为 AI 辅助区域，包含：
   - 输入框：用于输入辅助生成的提示文本。
   - 文件上传：支持上传文件作为 AI 生成的参考素材。
   - 提交按钮：提交右侧内容后调用 Dify 工作流接口。
4. Dify 工作流返回结果后，将返回信息自动填入左侧对应字段中。
5. 用户确认/调整左侧字段内容后，点击「保存」完成新增。

### 2.3 修改大客户档案
1. 在列表中点击某条记录进入编辑页面（左右分栏布局，同新增）。
2. 左侧回显当前档案的所有字段值。
3. 右侧 AI 辅助区域同新增流程，可再次调用 Dify 工作流补充或更新字段内容。
4. 保存前，系统自动对修改前的原始数据创建快照记录。
5. 用户确认修改后点击「保存」完成更新。

### 2.4 修改历史追溯
1. 每次修改操作保存前，系统自动快照记录修改前的完整原始信息。
2. 快照记录内容：修改时间、修改人、修改前各字段的完整值。
3. 支持查看某条档案的所有历史快照记录列表。
4. 支持查看某条快照的详细内容（修改前各字段值）。

## 3. 视觉优化需求

### 3.1 列表页
- 顶部操作栏：左侧为客户名称搜索输入框，右侧为「新增」按钮。
- 表格样式：统一边框、斑马纹交替行背景、hover 高亮。
- 分页组件：底部居中，展示总条数、当前页码、每页条数切换。

### 3.2 新增/编辑页（左右分栏）
- **左侧（表单区，约 50% 宽度）**：
  - 各字段纵向排列，每个字段带标签 + 多行文本输入框（textarea）。
  - 客户名称为单行输入，其余字段均为多行输入框，支持自动高度扩展。
  - 输入框支持换行符的保存与回显。
- **右侧（AI 辅助区，约 50% 宽度）**：
  - 顶部为提示文本输入框（多行）。
  - 中间为文件上传区域（支持拖拽上传和点击上传）。
  - 底部为「生成」提交按钮。
  - Dify 返回后，结果自动填入左侧对应字段，用户可在此基础上手动调整。
- 左右两栏之间以分割线区分。
- 底部操作栏：「保存」按钮 + 「取消」按钮。

### 3.3 历史记录页
- 以时间线或列表形式展示快照记录，按修改时间倒序排列。
- 每条记录展示：修改时间、修改人。
- 点击某条记录可展开查看修改前各字段的完整内容。

## 4. 技术实现

### 4.1 数据库设计

#### 主表：`key_accounts`
| 字段 | 类型 | 说明 |
|---|---|---|
| id | SERIAL PRIMARY KEY | 主键 |
| customer_name | VARCHAR(255) NOT NULL | 客户名称 |
| presales | TEXT | 售前 |
| basic_info | TEXT | 基本情况 |
| org_structure | TEXT | 组织架构 |
| business_needs | TEXT | 需求业务 |
| tech_integration | TEXT | 技术对接 |
| presales_pain_points | TEXT | 售前痛点 |
| youshi_involvement | TEXT | 优识介入 |
| solution | TEXT | 解决方案 |
| created_by | VARCHAR(100) | 创建人 |
| created_at | TIMESTAMP DEFAULT NOW() | 创建时间 |
| updated_by | VARCHAR(100) | 最后修改人 |
| updated_at | TIMESTAMP DEFAULT NOW() | 最后修改时间 |

#### 快照表：`key_account_snapshots`
| 字段 | 类型 | 说明 |
|---|---|---|
| id | SERIAL PRIMARY KEY | 主键 |
| account_id | INTEGER REFERENCES key_accounts(id) | 关联档案 ID |
| snapshot_data | JSONB NOT NULL | 修改前的完整原始数据（JSON 格式） |
| modified_by | VARCHAR(100) | 修改人 |
| modified_at | TIMESTAMP DEFAULT NOW() | 快照时间 |

### 4.2 后端 API

| 路由 | 方法 | 说明 |
|---|---|---|
| `/api/key-accounts` | GET | 分页查询大客户档案列表，支持 `keyword`（客户名称过滤）、`page`、`pageSize` 参数 |
| `/api/key-accounts` | POST | 新增大客户档案 |
| `/api/key-accounts/:id` | PUT | 修改大客户档案（修改前自动创建快照） |
| `/api/key-accounts/:id` | GET | 获取单条大客户档案详情 |
| `/api/key-accounts/:id/snapshots` | GET | 获取某条档案的所有历史快照记录 |
| `/api/key-accounts/:id/snapshots/:snapshotId` | GET | 获取某条快照的详细内容 |

### 4.3 Dify 工作流集成
- 右侧 AI 辅助区提交时，后端调用 Dify 工作流接口。
- 请求参数：右侧输入框文本 + 上传文件（文件上传走 Dify `/v1/files/upload` 中转，提取 `upload_file_id` 后传入工作流）。
- 工作流返回结果后，后端将结果返回前端，前端自动填入左侧对应字段。
- 遵循项目统一的 Dify 工作流对接模式（前端 → 后端 `/api/*` → Dify API）。
