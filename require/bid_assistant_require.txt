# 投标助手模块需求文档 (BidAssistantModule)

## 1. 功能描述
投标助手模块用于辅助用户编制标书文件。系统前期支持 .docx、.doc 两种文件格式，后续按需拓展其他格式（如 .pdf、.xlsx、.pptx）。用户上传标书文件后，系统自动识别文件类型并解析，支持多层级章节嵌套结构（章 → 节 → 小节），拆分出各章节内容进行展示。解析时需支持多种章节标题格式识别（如"第一章 招标公告"、"1. 总则"、"1.1 项目概况"等），并自动识别文档目录部分不将其作为正文章节。用户可逐章节编辑调整，支持配置固定内容模板（支持文本编辑与文件上传），一键替换到对应章节中，也支持调用 Dify 工作流生成内容替换到指定章节。所有章节内容调整完成后，系统自动拼接生成完整标书文件供用户下载。

## 2. 核心流程
1. 用户上传标书文件，支持 .docx、.doc 两种格式，后续按需拓展其他格式。系统自动识别文件类型并解析文件，支持多层级章节嵌套结构，拆分出各章节标题与内容进行展示。
2. 前端以分章节的形式展示解析结果，用户可逐章节查看和编辑内容。
3. 编辑过程中，系统自动保存当前编辑内容到后端，防止用户刷新页面后解析的内容丢失。
4. 用户可配置固定内容模板，模板支持文本编辑与文件上传两种方式。在编辑章节时，可一键将模板内容替换到当前章节中。
5. 用户可针对单个章节调用 Dify 工作流接口，拿到 Dify 生成的内容后替换到指定章节中。
6. 用户每个章节内容都调整完成后，系统自动将所有章节拼接成完整的标书文件供用户下载。

## 3. 视觉优化需求
- **章节导航**：左侧展示章节目录树，支持多层级嵌套结构（章 → 节 → 小节），点击可快速跳转到对应章节编辑区。
- **编辑区布局**：右侧为章节内容编辑区，顶部显示章节标题，下方为内容编辑器。章节内容中如包含表格，需保留表格结构进行展示和编辑。
- **自动保存状态提示**：编辑区显示保存状态（如"已自动保存"、"保存中..."、"保存失败"）。
- **一键替换交互**：编辑区提供"插入固定内容"按钮，点击后弹出模板列表，选择后替换到当前章节。
- **AI 生成交互**：编辑区提供"AI 生成"按钮，点击后展示加载状态，生成完成后结果填充到编辑器中。
- **整体风格**：与系统现有 UI 保持一致，使用 Tailwind CSS 进行样式定制。

## 4. 技术实现
- **文件解析**：后端接收上传文件，根据文件扩展名自动识别格式，使用对应解析库处理。解析时需支持多种章节标题格式识别（如"第一章 招标公告"、"1. 总则"、"1.1 项目概况"、"投标人须知前附表"等），支持多层级章节嵌套结构（章 → 节 → 小节），自动识别文档目录部分不将其作为正文章节，解析后按章节标题拆分，返回结构化的章节列表 `[{ title, content, order, level, children }]`。章节内容中如包含表格，需保留表格结构。
- **草稿自动保存**：前端使用防抖（debounce）策略，在用户停止编辑后自动调用后端草稿保存接口；后端以 JSON 格式存储各章节编辑内容，关联用户 ID 与解析任务 ID。
- **固定内容模板**：后端提供模板的 CRUD 接口，模板支持文本编辑和文件上传两种内容形式，上传的文件由后端解析后存储内容，存储于数据库。
- **Dify 工作流调用**：后端遵循项目统一的 Dify 对接模式，将章节标题与内容作为 inputs 传入工作流，解析返回结果后填充到对应章节。
- **标书生成下载**：后端将所有章节按 order 排序拼接，生成完整文件，返回文件流供前端下载。
- **前端组件**：使用 React + TypeScript 开发，通过 Tailwind CSS 定制样式。
