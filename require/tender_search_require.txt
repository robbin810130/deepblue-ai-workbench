# 招标检索模块需求文档 (TenderSearchModule)

## 1. 功能描述
招标检索模块是一个基于 Dify 工作流的招标信息智能检索工具。用户输入日期范围和筛选条件后，系统调用 Dify 工作流检索招标公告，按相关性排序，自动生成 Excel 报表和中文摘要分析报告。支持跨次查重过滤历史记录。

## 2. 核心流程
1. 用户输入开始日期、结束日期（必填，格式 YYYY-MM-DD），可选设置返回条数（默认 100，范围 1-500）和跨次查重开关（默认开启）。
2. 后端校验日期格式与逻辑（开始 ≤ 结束），转换查重开关为布尔值。
3. 后端调用 Dify `tender-search` 工作流，传入检索参数。
4. 工作流返回检索结果 JSON，后端提取统计指标并判断成功/失败。
5. 成功时由 Dify LLM 节点生成中文摘要报告；失败时返回错误提示与排查建议。
6. 前端渲染摘要报告 + 底部检索统计栏（记录数、API 调用次数、爬取成功数、Excel 报表文件名）。

## 3. 视觉优化需求
- **统计摘要栏**：结果顶部展示关键指标卡片（检索记录数、API 调用次数、爬取成功/总数、查重过滤数），图标 + 数字紧凑布局。
- **分布分析**：业务类型分布和渠道类型分布使用小型饼图或横向柱状图展示。
- **招标明细列表**：Top 10 招标信息采用卡片式或表格展示，包含投标方名称、项目全称、业务类型标签、项目金额（高亮）、地区、截止时间等字段。
- **Excel 下载入口**：结果底部提供 Excel 报表下载按钮，文件名清晰可见。
- **错误状态**：失败时使用警告样式，列出可能原因和建议操作，提供"重新检索"入口。
- **加载状态**：检索耗时较长，需展示进度提示。
- **美观性**：结果框应具有现代感，背景、内边距和动画效果应与整体 UI 保持一致。

## 4. 技术实现

### 前端
- **组件文件**：`src/components/TenderSearchModule.tsx`
- **交互模式**：对话式（advanced-chat），用户输入参数后触发检索，流式返回结果。
- **结果渲染**：使用 `ReactMarkdown` 配合 `remarkGfm` 和 `rehypeRaw` 渲染 LLM 摘要，统计指标使用独立 UI 组件。
- **利用 Tailwind CSS 进行样式定制。**

### 后端
- **路由前缀**：`/api/tender-search/`
- **主要接口**：
  | 接口 | 方法 | 说明 |
  |------|------|------|
  | `/run` | POST | 触发 Dify 招标检索工作流 |
- **Dify 对接**：
  - 工作流名称：`tender-search`（advanced-chat 模式）
  - 调用方式：`POST /v1/chat-messages`
  - 请求参数（通过 workfow inputs 传入）：
    | 参数 | 类型 | 必填 | 默认值 | 说明 |
    |------|------|------|--------|------|
    | `begin_date` | string | 是 | — | 开始日期，格式 YYYY-MM-DD |
    | `end_date` | string | 是 | — | 结束日期，格式 YYYY-MM-DD |
    | `top_n` | number | 否 | 100 | 返回条数，范围 1-500 |
    | `dedup` | string | 否 | "是" | 跨次查重开关（"是"/"否"） |
  - 工作流输出（answer 节点）：LLM 生成的中文摘要报告
  - 工作流中间输出（通过节点变量获取）：success、message、items_count、api_calls、scrape_success、scrape_total、dedup_removed、excel_filename、biz_type_distribution、channel_distribution
- **输出字段（15 个）**：投标方名称、项目全称、业务类型、项目金额、渠道类型、投标所在地区、入围商家数量、预算金额、文件获取时间、文件获取方式、招标文件费用、投标截止时间、应标方式、来源网站、跳转链接
- **Dify 配置**：`DIFY_TENDER_SEARCH_API_KEY`、`DIFY_TENDER_SEARCH_API_URL`（.env 配置）

### 关键约束
- 日期格式严格校验为 `YYYY-MM-DD`，开始日期不得晚于结束日期。
- `top_n` 范围限制 1-500，超出范围需前端拦截或后端兜底。
- 跨次查重由工作流内部处理，首次检索无过滤效果。
- Excel 报表生成在服务器 `outputs` 目录，需确保磁盘空间和写入权限。
- 检索耗时较长，前端需设置合理超时（建议 120s+）。
