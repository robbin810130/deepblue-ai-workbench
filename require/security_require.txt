# 会话安全模块 (Session Security) 需求文档

## 1. 业务目标
增强系统的准入安全与会话控制能力，防止 Token 长期有效带来的泄露风险，并实现多端登录冲突管理。

## 2. 核心功能计划

### 2.1 JWT 过期策略
- **Token 有效期**: 从原有的 7 天缩短至 **2 小时**。
- **强制失效**: 当用户修改密码或被管理员禁用时，所有相关 JTI 必须在数据库中标记为 `revoked`。

### 2.2 强制登出 (Force Logout)
- **退出登录接口**: 新增 `/api/auth/logout`。
- **逻辑**: 调用后立即在 `sys_user_sessions` 表中将当前会话的 `jti` 状态更新为 `revoked = TRUE`。
- **前端集成**: 用户点击全局退出按钮时，必须显式调用此接口，而非仅仅清除本地 `localStorage`。

### 2.3 并发登录限制
- **限制数量**: 每个账号最多允许同时在线 **5 个** 会话（设备）。
- **冲突策略**: 当达到上限并有新登录发生时，系统**拒绝登录请求**，并提示用户已达到最大会话限制。
- **目的**: 保护正在执行长任务（如 AI 智能体分析）的现有会话不被意外中断。
- **处理建议**: 提示用户在已登录设备上通过“个人中心”手动踢出闲置设备。


### 2.4 动态数据脱敏 (Dynamic Data Masking)
- **目标**: 根据用户角色动态屏蔽敏感资料（客户名、手机号、金额、产品名）。
- **策略**: 
  - `admin` 角色：查看原始数据。
  - 其他角色（`salesman`, `user`, `data_analyst` 等）：查看掩码后的脱敏数据。
- **覆盖范围**:
  - `/api/customer-analysis`
  - `/api/deviation-alerts`
  - `/sales_analysis_matrix.json` (拦截器)
  - `/monthly_forecast_baseline.json` (拦截器)

## 3. 技术实现要点
- **后端拦截**: 在 `server.js` 中通过 `authenticateToken` 中间件判定角色，并在返回 JSON 前调用 `utils/maskingUtils.js` 进行处理。
- **静态文件过滤**: 对敏感静态 JSON 文件设置专门的 GET 路由，抢占 `express.static` 的优先级以实现动态脱敏。
- **数据库优化**: 为 `sys_user_sessions` 的 `user_id` 和 `jti` 建立索引（已完成部分，需确认）。
- **清理任务**: 定期清理 `expires_at < NOW()` 且超过一定时间（如 30 天）的陈旧会话记录。
